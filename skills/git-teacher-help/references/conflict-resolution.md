# 충돌 해결 — 덩어리 단위로 합치기

save·status·review·upload 스킬이 모두 이 절차를 따른다. **파일 하나를 통째로 "내 것" 또는 "상대 것"으로 고르는 방식은 기본으로 쓰지 않는다.** 그렇게 하면 같은 파일 안에서 충돌이 아닌 부분까지 한쪽 수정이 통째로 사라진다.

## 절차

1. **충돌 파일 찾기**
   ```bash
   git diff --name-only --diff-filter=U
   ```
2. **덩어리(hunk) 읽기** — 파일마다 `<<<<<<<` ~ `=======` ~ `>>>>>>>` 구간을 Read로 읽는다. 충돌 표시 밖의 부분은 Git이 이미 양쪽 수정을 합쳐 놓은 것이므로 건드리지 않는다.
3. **쉬운 말로 설명** — 덩어리마다 한두 줄로:
   - "내가 작업한 부분: 버튼 글자를 '구매'로 바꿨어요"
   - "상대방이 작업한 부분: 같은 버튼 색을 파란색으로 바꿨어요"
   - 기술 용어(HEAD, incoming, current change) 금지 — `gotchas.md` 용어 규칙을 따른다.
4. **에이전트가 먼저 합친다** — 두 수정이 함께 살 수 있으면(서로 다른 속성, 목록에 각자 항목 추가, 한쪽은 이름 변경·한쪽은 내용 수정 등) 둘 다 반영한 결과를 만들고, "둘 다 살려서 이렇게 합쳤어요"라고 결과를 보여 준다.
5. **정말 부딪히는 덩어리만 사용자에게 묻는다** — 같은 문장을 서로 다른 뜻으로 바꿨을 때처럼 의도가 충돌하는 덩어리만 AskUserQuestion으로 고르게 한다. 덩어리마다 한 질문, 옵션은 세 개:
   ```json
   {
     "questions": [{
       "question": "{파일} 의 이 부분은 두 분의 의도가 달라요.\n- 내 쪽: {한 줄 설명}\n- 상대 쪽: {한 줄 설명}\n어느 쪽으로 할까요?",
       "header": "충돌 한 곳",
       "options": [
         {"label": "내 쪽으로", "description": "이 부분만 내가 고친 내용을 써요"},
         {"label": "상대 쪽으로", "description": "이 부분만 상대방이 고친 내용을 써요"},
         {"label": "둘 다 살려서 합쳐 줘", "description": "에이전트가 두 의도를 섞은 안을 만들어 보여줘요"}
       ],
       "multiSelect": false
     }]
   }
   ```
   한 번에 최대 4개 덩어리까지 한 AskUserQuestion에 묶는다.
6. **확인 후 표시** — 충돌 표시가 남지 않았는지 확인하고 해결 표시를 한다.
   ```bash
   grep -nE '^(<<<<<<<|=======|>>>>>>>)' {파일} || echo "표시 없음"
   git diff --check
   git add {파일}
   ```
   merge 중이면 다음 단계(저장)로, `git pull --rebase` 중이면 `git rebase --continue`로 이어 간다.
7. **영수증** — 파일마다 "자동으로 합친 곳 N개, 고르신 곳 M개"를 알려 준다.

## 파일 통째 선택이 허용되는 경우

사용자가 "이 파일은 통째로 내 걸로"처럼 **파일 전체를 한쪽으로** 하겠다고 직접 말한 경우에만 한다. 이때도 먼저 "이 파일에서 상대방이 고친 다른 부분 N곳도 같이 사라져요"라고 알려 주고 확인받는다.

- rebase(`git pull --rebase`) 중에는 ours/theirs 뜻이 merge와 **반대**다 — ours가 상대방(받아온 쪽), theirs가 내 커밋이다. 헷갈리면 덩어리 단위 절차로 돌아간다.

## 겁먹은 사용자에게

"Git이 대부분은 알아서 합쳤고, 두 분이 같은 줄을 고친 곳만 남겨 둔 거예요. 아무것도 사라지지 않았어요."로 시작한다. 충돌 중에는 `git merge --abort`(또는 `git rebase --abort`)로 시작 전 상태로 언제든 돌아갈 수 있다는 것도 알려 준다.
